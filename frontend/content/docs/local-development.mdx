## Prerequisites

- Python 3.11+
- Node.js 20+
- Git
- optional vendor API key if you want to run against a real LLM provider

## Important boundaries

The production path is:

- `backend/src/quorum_backend/main.py`
- `backend/src/quorum_backend/pipeline/router.py`
- `frontend/components/workspace/quorum-pipeline.tsx`

If you touch architecture, start there. The older split simulation surface and
unused workspace branch have been removed.

## Backend setup

```bash
python -m venv backend/.venv
# Windows
backend\.venv\Scripts\activate
# macOS / Linux
# source backend/.venv/bin/activate
pip install -e "backend[dev]"
```

Run the backend from the repository root:

```bash
python -m uvicorn quorum_backend.main:app --reload --port 8000
```

## Frontend setup

```bash
cd frontend
npm install
npm run dev
```

## Environment configuration

Create `.env.local` in the repository root and set one of the supported
providers:

```env
LLM_PROVIDER=google
GOOGLE_API_KEY=...
GOOGLE_MODEL=gemini-1.5-flash
```

For offline work you can also use:

```env
LLM_PROVIDER=local
```

That local deterministic provider is sufficient for the production pipeline
tests and for basic development.

## Verification loop

Backend tests:

```bash
backend\.venv\Scripts\python -m pytest backend\tests -q
```

Frontend production build:

```bash
cd frontend
npm run build
```

## When changing the pipeline

Move through this order:

1. update backend models or router
2. update stage services
3. update frontend types and workspace cards
4. update Fumadocs pages
5. run backend tests
6. run the frontend build

The refactor deliberately made code and docs move together. Keep that standard.

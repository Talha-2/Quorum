Base URL by default:

```text
http://localhost:8000
```

All endpoints return JSON except file upload, which accepts multipart form
data.

## Health

### `GET /health`

Returns service, version, provider status, and project-store information.

Example response:

```json
{
  "status": "healthy",
  "service": "Quorum",
  "version": "1.0.0",
  "llm_provider_configured": "google",
  "llm_provider_active": "google",
  "llm_provider_ok": true,
  "project_count": 3,
  "project_store_path": "/app/data/projects.pkl"
}
```

## Projects

### `POST /api/projects`

Create a project.

Request body:

```json
{
  "title": "Optional title",
  "brief": "Should the team launch the new coordination workflow next quarter?",
  "constraints": "Budget is fixed\nCompliance review cannot slip",
  "signals": "Customer demand is rising"
}
```

### `GET /api/projects/{project_id}`

Fetch the full serialized project, including the latest pipeline state and
available artifacts.

### `GET /api/projects/{project_id}/pipeline`

Fetch canonical pipeline progress.

Example response:

```json
{
  "project_id": "proj_123",
  "state": "config_ready",
  "failed": false,
  "last_error": null,
  "current_step": "activate",
  "steps": [
    {
      "id": "prepare",
      "order": 5,
      "label": "Simulation config",
      "detail": "Time, activity, and platform config",
      "path": "/api/projects/proj_123/simulation/prepare",
      "done": true,
      "optional": false
    }
  ]
}
```

## Stage 0: Upload

### `POST /api/projects/{project_id}/upload`

Upload a reality-seed document before ontology generation starts.

Request example:

```bash
curl -X POST http://localhost:8000/api/projects/proj_123/upload \
  -F "file=@seed.txt"
```

Supported types:

- `.pdf`
- `.md`
- `.markdown`
- `.txt`

Important rule:

- uploads are rejected with `409` once ontology generation has started

## Stage 1: Ontology

### `POST /api/projects/{project_id}/graph/ontology/generate`

Generate the ontology for the project.

Response updates:

- `state = "ontology_generated"`
- `ontology`
- `pipeline.current_step = "graph"`

## Stage 2: Graph

### `POST /api/projects/{project_id}/graph/build`

Generate the knowledge graph.

Response updates:

- `state = "graph_completed"`
- `graph`
- `graph_stats`

## Stage 3: Environment setup

### `POST /api/projects/{project_id}/env/setup`

Generate agent personas.

Response updates:

- `state = "env_ready"`
- `agents`
- `agent_count`

## Stage 4: Simulation config

### `POST /api/projects/{project_id}/simulation/prepare`

Generate structural simulation configuration.

Response updates:

- `state = "config_ready"`
- `simulation_parameters`

Shape:

```json
{
  "simulation_parameters": {
    "time_config": {},
    "agent_configs": [],
    "event_config": null,
    "feed_config": {},
    "community_config": {},
    "generation_reasoning": "..."
  }
}
```

## Stage 5: Initial activation

### `POST /api/projects/{project_id}/simulation/activate`

Generate the activation plan.

Response updates:

- `state = "activation_ready"`
- `activation`

Shape:

```json
{
  "activation": {
    "initial_posts": [
      {
        "content": "Starter post text",
        "poster_type": "MediaOutlet",
        "poster_agent_id": 2
      }
    ],
    "scheduled_events": [],
    "hot_topics": ["execution-risk", "timing"],
    "narrative_direction": "Early discussion centers on risk and accountability...",
    "generated_at": "2026-04-23T12:00:00+00:00"
  }
}
```

## Stage 6: Simulation

### `POST /api/projects/{project_id}/simulation/start`

Start the round-based debate.

Request body:

```json
{
  "rounds": 3,
  "agents_per_round": 4
}
```

Response updates:

- `state = "sim_completed"`
- `debate_messages`
- `consensus`

## Stage 7: Report

### `POST /api/projects/{project_id}/report/generate`

Generate the markdown report.

Response updates:

- `state = "report_ready"`
- `report`

## Sequential helper

### `POST /api/projects/{project_id}/pipeline/run-next`

Run the next incomplete required stage exactly once.

Request body:

```json
{
  "rounds": 3,
  "agents_per_round": 4
}
```

`rounds` and `agents_per_round` are only used when the next stage is the
simulation stage.

## Agent chat

### `POST /api/projects/{project_id}/agents/{agent_id}/chat`

Ask a question to one specific agent after a run.

Request body:

```json
{
  "message": "What is the gating risk from your perspective?"
}
```

Response:

```json
{
  "agent_id": "agent_123",
  "agent_name": "Program Lead",
  "user_message": "What is the gating risk from your perspective?",
  "reply": "..."
}
```

## Serialized project shape

Every mutating stage returns the full project snapshot.

Key top-level fields:

```typescript
interface Project {
  id: string
  title: string
  brief: string
  constraints: string
  signals: string
  state: ProjectState
  created_at: string
  updated_at: string
  last_error?: string | null
  ontology: Ontology | null
  graph_stats: GraphStats | null
  graph?: PipelineGraph
  agent_count: number
  agents?: AgentProfile[]
  simulation_parameters?: SimulationParameters
  activation?: EventConfig
  debate_messages?: DebateMessage[]
  consensus?: Consensus
  report?: Report
  uploaded_documents?: UploadedDocumentMeta[]
  events: PipelineEvent[]
  pipeline: PipelineProgress
}
```

## Error conventions

Typical status codes:

- `400` for malformed input
- `404` for missing project or agent
- `409` for invalid stage ordering or frozen inputs
- `500` for stage execution failure after validation

Quorum turns an open-ended brief into a structured, inspectable multi-agent run.
You create a project, attach reality-seed documents, step through a strict
seven-stage pipeline, and finish with a debate transcript, consensus, report,
and post-run agent chat.

This documentation set is the canonical source of truth for the repository.
The older root-level markdown docs are no longer the product reference.

## Flow at a glance

The pipeline is intentionally linear. Each stage has one job, one persisted
output, and one set of prerequisites enforced by the backend.

![Quorum production pipeline flow chart](/docs-images/pipeline-flow.svg)

*Flow chart: project creation and optional uploads feed a strict server-side
stage sequence from ontology to report.*

## What Quorum does

Quorum is designed for questions that need explicit disagreement, not a single
compressed answer. The system:

1. Builds a project from a brief and optional source documents.
2. Generates a topic-specific ontology.
3. Extracts a typed knowledge graph.
4. Instantiates one agent per speaker-capable entity.
5. Generates simulation configuration.
6. Generates an activation plan that seeds the debate.
7. Runs a structured multi-round simulation.
8. Produces a report and supports follow-up chat with any agent.

The pipeline is intentionally sequential. Each stage validates its
prerequisites, persists its output, and exposes enough intermediate state to
debug the run without guessing.

## Product principles

- **One production path**: the repository now centers on the project-based
  `/api/projects/*` pipeline. The previous legacy simulation surface has been
  removed.
- **Typed artifacts over ad hoc prompts**: ontology, graph, agents, config,
  activation, transcript, consensus, and report are all persisted project
  artifacts.
- **Strict stage ordering**: uploads happen before ontology, activation happens
  before simulation, and report generation happens only after a completed run.
- **Offline-verifiable**: the local deterministic LLM provider now understands
  the production pipeline prompts, so the end-to-end path is testable without a
  vendor API.
- **Documentation in the app**: the Fumadocs site under `/docs` is the primary
  documentation surface and ships with the product.
